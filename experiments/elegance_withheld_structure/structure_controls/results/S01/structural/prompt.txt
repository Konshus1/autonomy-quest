Provide objects that turn a message record into text. Optional capabilities must include adding a subject block, redacting configured fields, appending a legal notice, and recording rendering metadata. Capabilities may be combined in any order, duplicate application must have documented deterministic behavior, and the original message record must remain unchanged. Existing capabilities must work with user-supplied renderers satisfying the public rendering contract. Tests must use only unittest and the standard library. Organize the implementation explicitly as Decorator: every optional capability is a composable wrapper implementing the same public callable contract and delegating to one inner callable.

PUBLIC INTERFACE CONTRACT (part of the requirement, not an implementation hint)
Create solution.py exporting:
- base_renderer(message): returns {"text": message["body"], "metadata": []} using copies.
- subject(template="Subject: {subject}"): capability value.
- redact(fields, replacement="[REDACTED]"): capability value. It replaces every string value of each named message field wherever that exact value appears in the current text.
- legal(text): capability value appending the notice on a new line.
- record(label): capability value appending label to result metadata without changing text.
- make_renderer(renderer, capabilities): returns a callable accepting a message dict and returning exactly {"text": str, "metadata": list[str]}.
Capabilities apply in list order. Repeating an equivalent capability is ignored after its first occurrence. The input message and the renderer's returned value must not be mutated. A user renderer is any callable with the same input/result contract.
Use only the Python standard library.
