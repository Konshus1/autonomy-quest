Implement `meeting.py`. An agenda has numbered items, nested subitems, presenters, supporting documents, expected durations, consent-group membership, and private staff notes. During the meeting, record reorderings, withdrawals, motions, votes, recesses, and actual timestamps. Produce the pre-meeting public agenda, chair’s run sheet, final minutes, action-item register, and a comparison of planned versus actual sequence and duration. Original item numbers remain valid references after reorder or withdrawal. Invalid events must be reported together rather than stopping at the first.

Executable acceptance contract: Use fixed datetimes; create nested items and consent group, reorder and withdraw one, record motion/roll-call/tie and recess; assert all five exact views, stable original references, duration comparison, action extraction, and aggregation of a bad item reference plus impossible event order. Use only the Python standard library.

Public API/data-format contract: Provide `Meeting(agenda)`. The agenda is `{meeting_id,start,items,consent_groups}` using `datetime.datetime` values; items are recursive `{number,title,presenter,documents,expected_minutes,private_notes,subitems,action}` dicts, and original `number` strings are unique permanent references. The object accepts calls `reorder(order, at)`, `withdraw(item, at)`, `add_motion(item, text, at) -> motion_ref`, `record_vote(item, motion_ref, votes, at)`, and `add_recess(start, end)`. Votes map member names to `yes`, `no`, or `abstain`. Calls do not raise for meeting-data errors; they accumulate them. `documents() -> dict` returns exactly `{public_agenda,chair_run_sheet,minutes,actions,comparison,errors}` and may be called repeatedly without changing the result. Public agenda is the original recursive agenda without private notes/actions. Chair run sheet adds private notes and consent-group name or null. Minutes is a chronological list with exact entry shapes: reorder `{type:'reorder',order,at}`, withdrawal `{type:'withdraw',item,at}`, motion `{type:'motion',item,text,ref,at}`, vote `{type:'vote',item,ref,votes,result,at}`, and recess `{type:'recess',minutes,at}`. Datetimes render as ISO text; vote result is `passed`, `failed`, or `tie` after excluding abstentions, and recess minutes are integers. Actions is sorted `{item,action}` entries for nonwithdrawn items. Comparison has one row per top-level planned item: `{item,planned_position,actual_position,expected_minutes,actual_minutes,status}`; withdrawn position is null, and status is `withdrawn`, `moved`, or `as_planned`. Actual minutes run from the first proceeding for an item until the next proceeding for a different item or the last proceeding, less recess overlap; an item with none has zero. Errors are sorted and include all applicable `unknown item X`, `timestamps out of order`, `recess ends before it starts`, and `invalid reorder`; invalid calls do not alter the five document views. Inputs are not mutated. The API does not constrain whether an implementation annotates agenda copies, keeps parallel state, uses commands, snapshots, or another design.
