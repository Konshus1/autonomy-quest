Public API and data-format contract (the implementation's internal organization is unrestricted):
A packet is a dictionary with `greeting`, `free_text`, `address` (a list of lines), `facts` (a list of `{"label", "value", "sensitivity"}` where sensitivity is `public` or `sensitive`), optional `table` (a list of equal-length row lists), `action` (one `{"label", "url", "sms_alias"}` dictionary, a list of such dictionaries, or `None`), `legal`, and `signoff`. Inputs are not mutated. Provide `render_html(packet)`, `render_text(packet)`, `render_print(packet, width, height)`, and `render_sms(packet, budget)`. Channel handling for sensitive fact values is: HTML shows them, plain email masks all but the final four characters with `*` (or all characters if shorter than four), print omits those fact lines, and SMS omits them.
HTML returns these blocks in order: `<p class="greeting">`, `<p class="body">`, `<address>` with `<br>` between lines, `<dl>` facts, an optional `<table>` with `<tr><td>...</td></tr>`, one optional `<p class="action"><a href="URL">LABEL</a></p>` per action, `<p class="legal">`, and `<p class="signoff">`; all supplied text and attributes use `html.escape(..., quote=True)`. Address and legal are indivisible blocks: if either has more than `height` lines, raise `ValueError`; if it will not fit on the current page it begins on the next page. No blank separator is placed at the top or bottom of a page. SMS is `greeting free_text [public facts as "label: value"] [action as "label sms_alias"] legal signoff`, joining present pieces with one ASCII space. If over budget, remove public facts from the end, then omit free text, then omit greeting, then omit signoff; actions and legal are never removed. If still over budget raise `ValueError`.
