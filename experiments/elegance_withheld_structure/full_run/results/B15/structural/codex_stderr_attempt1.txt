Implement `approval.py`. Packaging assets have regions (front, back, side), text claims, colors, images, and supplied checksum. Reviewers in legal, brand, and accessibility can approve, reject, comment, or supersede their prior review. A release candidate may reuse regions from earlier candidates. Changing a region must stale only reviews whose scope included it.

Executable acceptance contract: Use `hashlib`, `io.BytesIO`, and `zipfile`; build candidates reusing/changing regions, assert scoped staleness, superseded review behavior, policy explanation, region ancestry, diff, byte-for-byte deterministic ZIP, fixed `ZipInfo.date_time`, manifest checksum verification, and no readiness mutation during export. Use only the Python standard library.

Public API/data-format contract: `assess(candidate, reviews, policy, prior_candidates) -> dict`, `compare(a, b) -> dict`, and `export_dossier(candidate, reviews, policy, prior_candidates) -> bytes`. Inputs are JSON-shaped snapshots. A candidate is `{id,based_on,regions}` where `based_on` is a prior candidate ID or null and each region is `{text_claims,colors,images,checksum}`. The supplied checksum must equal lowercase SHA-256 of compact sorted-key JSON of the other three fields. A review submission is `{id,candidate,department,decision,scope,comment,supersedes}` with decision `approve|reject|comment`; scope is a sorted list of region names, and supersedes is a prior review ID or null. Policy has `{required_departments,required_regions}`. `prior_candidates` maps IDs to complete candidate snapshots. `assess` returns `{ready,blockers,stale,superseded,ancestry}` with sorted lists. The latest valid superseding submission from a department controls; superseded IDs are reported. An approval remains usable on a later candidate for the regions in its scope that are byte-for-byte unchanged through the supplied candidate lineage, and becomes stale only for scoped regions that changed. Each required department needs usable approval coverage of every required region. Blockers use `DEPT missing approval`, `DEPT rejected: COMMENT`, or `DEPT approval lacks REGION`; stale entries use `REVIEW stale: REGION`. `ancestry` is a sorted list with one plain-language line per current region: `REGION: introduced in ID`, `REGION: unchanged from ID through ID`, or `REGION: changed in ID (previous ID)`. It is an explanatory report derived by comparing snapshots; no region carries an ancestry key or identity derived from content. `compare` returns sorted `{added,removed,changed,unchanged}` region names, comparing complete region content and checksum. Export returns a stored ZIP with members `candidate.json`, `reviews.json`, `readiness.json`, and `checksums.json` in that order. JSON is compact sorted-key UTF-8. Each `ZipInfo.date_time` is `(1980,1,1,0,0,0)` and `create_system` is 0 and `external_attr` is `0o600 << 16`. `checksums.json` maps the other three names to SHA-256 digests.
