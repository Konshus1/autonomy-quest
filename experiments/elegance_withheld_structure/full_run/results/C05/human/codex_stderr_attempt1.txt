Provide objects that turn a message record into text. Optional capabilities must include adding a subject block, redacting configured fields, appending a legal notice, and recording rendering metadata. Capabilities may be combined in any order, duplicate application must have documented deterministic behavior, and the original message record must remain unchanged. Existing capabilities must work with user-supplied renderers satisfying the public rendering contract. Tests must use only unittest and the standard library.

Public API and data-format contract (frozen):
The module must export `present(message, renderer, capabilities)`. `message` is a mapping and must not be mutated. `renderer` is any user-supplied object with `render(message) -> str`. `capabilities` is a sequence of dictionaries. Supported forms are `{"kind":"subject", "text": str}`, `{"kind":"redact", "fields": [str,...]}`, `{"kind":"legal", "text": str}`, and `{"kind":"metadata", "key": str, "value": JSON-compatible value}`. Unknown kinds or malformed entries raise `ValueError` without calling the renderer.

`present` returns `Presentation(text, metadata)`, where `Presentation` is an exported frozen dataclass with public `text: str` and `metadata: dict`. Processing is deterministic and independent of capability ordering: all configured fields are replaced in a shallow copy of the message by the literal string `[REDACTED]` before exactly one renderer call; distinct subject texts are sorted and prepended as lines `Subject: <text>`; distinct legal texts are sorted and appended as lines; metadata keys are returned sorted by key. Repeating an identical subject, legal text, redacted field, or identical metadata key/value has no further effect. Conflicting values for the same metadata key raise `ValueError` without calling the renderer. Subject and legal sections are separated from the rendered body by one newline, and absent sections add no newline. Redaction applies only to the mapping handed to the renderer, not to text added by the other capabilities.
